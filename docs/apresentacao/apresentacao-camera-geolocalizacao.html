Tópico 1 • Contextualização

O Problema e a Solução Pericial

Regras de Negócio NBR 5674
⚠️ O Problema em Vistorias Condominiais

• Vistorias "de Gabinete": Laudos emitidos sem a presença física real do inspetor nas áreas críticas do condomínio.
• Perda de Sinal Crítica: Garagens no subsolo (G2/G3) e casas de máquinas são gaiolas de Faraday sem sinal de internet.
• Fragilidade Probatória: Fotos adulteráveis, sem hash de integridade, armazenadas em galerias voláteis ou base64 pesado.
• Omissão de Anomalias Críticas: Vistorias concluídas sem registro fotográfico de patologias graves.

🛡️ A Solução Implementada no SindiFlow

• Geolocalização Mandatória (RF-VIST-004): Captura de GPS em alta precisão vinculada à sessão de vistoria, impedindo finalização sem presença comprovada.
• Câmera Pericial Padronizada (RNF08): Captura nativa, compressão máxima de 1080p e geração de hash SHA-256 de integridade da evidência.
• Persistência Offline Local (Obrigações §1.2): Gravação imediata em SQLite no celular, garantindo zero perda de dados no subsolo.
• Matriz de SLA & Foto Mandatória (§3.2): Ocorrências de gravidade ALTA exigem evidência fotográfica obrigatória.

🎙️ Roteiro de Fala — Minuto 1:00 a 2:15

"O grande desafio das vistorias prediais é a idoneidade jurídica. Sem prova de presença física e integridade das fotos, laudos técnicos são facilmente contestados. No SindiFlow, geolocalização e câmera não são features decorativas: são invariantes de domínio. O sistema bloqueia a finalização se o perito não estiver com GPS capturado e exige foto para qualquer anomalia de gravidade ALTA, funcionando 100% offline no subsolo."

Tópico 2 • Arquitetura

Clean Architecture & DDD: Onde Moram Câmera e GPS?

Regra de Dependência Estrita
🎯 1. Domínio Puro

Zero imports de SDKs externos.
• Geolocalizacao (Value Object imutável, limites -90..90 e -180..180).
• Evidencia (Value Object com hash SHA-256 e URI local).
• ICameraGateway e ILocationGateway (Interfaces definindo contratos puros).

⚡ 2. Casos de Uso

Orquestração de regras de negócio.
• CapturarLocalizacaoUseCase: obtém e valida posição pericial.
• AnexarFotoUseCase: valida alvo antes de abrir obturador, limita a 1080p e grava no SQLite.
• FinalizarVistoriaUseCase: bloqueia sem GPS e valida os ≥80% do checklist.

🔌 3. Adapters & Infra

A infraestrutura se curva ao domínio.
• CameraGatewayExpo (expo-image-picker).
• LocationGatewayExpo (expo-location).
• VistoriaRepositorySQLite (expo-sqlite).
• Fakes determinísticos para execução de testes velozes.

📷 Onde Vai a CÂMERA?

• Nos Itens do Checklist: Anexada ao ItemChecklist como evidência visual de integridade ou avaria.
• Nas Ocorrências Críticas (§3.2): Anexo fotográfico mandatório para anomalias com SLA de 24h (Gravidade ALTA).
• No FileSystem + SQLite: Arquivo comprimido em máx 1080p no disco físico, indexado no SQLite por hash SHA-256 (nunca base64).

📍 Onde Vai o GPS MANDATÓRIO?

• Na Sessão de Vistoria (Não por foto): Obedece a regra §1.4 evitando dispersão de coordenadas avulsas.
• Gatilho Mandatório na Conclusão (RF-VIST-004): Invariante de domínio — o método vistoria.finalizar(geolocalizacao) lança erro se executado sem satélite.
• Assinatura Pericial de Presença: Certifica juridicamente (NBR 5674) que o inspetor esteve fisicamente no edifício no momento do laudo.

🎙️ Roteiro de Fala — Minuto 2:15 a 3:45

"Onde exatamente entram a Câmera e o GPS? A Câmera entra vinculada a cada Item de Checklist e Ocorrência de Gravidade Alta como um Value Object Evidencia, com hash e caminho físico em disco. Já o GPS MANDATÓRIO não é tirado por foto: ele entra na Sessão de Vistoria, disparado compulsoriamente pelo Caso de Uso FinalizarVistoria (RF-VIST-004). Sem as coordenadas do satélite, o Domínio se recusa a concluir a inspeção, assegurando que o laudo técnico comprove a presença física do inspetor no condomínio."

Tópico 3 • Estratégia de Testes

Como Testamos Câmera e Geolocalização sem Hardware Físico?

TDD: Red → Green → Refactor
🧪 Como Foi Feito (Estratégia de Dublagem)

1. Gateway Fakes com Estado Controlável:
Criamos CameraGatewayFake e LocationGatewayFake para testes dos Casos de Uso. Permitem simular permissão concedida, permissão negada, cancelamento do usuário e coordenadas customizadas.

2. Mocks de Módulos Nativos para os Adapters:
Nos testes dos adaptadores Expo (camera.gateway.expo.spec.ts e location.gateway.expo.spec.ts), isolamos as chamadas da ponte nativa com spies jest sobre as funções assíncronas do SDK.

✅ Nossos Testes Garantem que:
  • • Permissão Negada: Lança PermissaoNegadaError com mensagem clara ao usuário.
  • • Cancelamento Gracioso: Se o usuário fechar a câmera sem bater foto, retorna { status: 'cancelado' } sem gerar erro ou arquivos órfãos.
  • • Compressão 1080p: Dimensões máximas e qualidade são repassadas com fidelidade.
  • • Hash Obrigatório (RF-EVI-001): Toda foto capturada gera hash para garantia de integridade.
  • • Bloqueio de Finalização (RF-VIST-004): Vistoria sem coordenadas rejeita finalização.

Tópico 4 • Contratos

O Domínio e as Interfaces (A Base do Contrato)

src/domain/interfaces
Contrato da Câmera (ICameraGateway)
export interface FotoCapturada { uri: string; // file:///... no FileSystem largura: number; // máx 1080p (RNF08) altura: number; tamanhoBytes: number; hash: string; // RF-EVI-001 timestamp: Date; } export type ResultadoCaptura = | { status: 'sucesso'; foto: FotoCapturada } | { status: 'cancelado' } | { status: 'erro'; mensagem: string }; export interface ICameraGateway { temPermissao(): Promise<boolean>; solicitarPermissao(): Promise<boolean>; capturarFoto(opts?: CapturaFotoOptions): Promise<ResultadoCaptura>; }
Contrato de Localização (ILocationGateway)
export interface LocalizacaoDispositivo { latitude: number; // -90 a 90 longitude: number; // -180 a 180 precisao?: number; // em metros timestamp?: Date; } export interface ILocationGateway { temPermissao(): Promise<boolean>; solicitarPermissao(): Promise<boolean>; obterPosicaoAtual(): Promise<LocalizacaoDispositivo>; }
Por que ResultadoCaptura é uma Discriminated Union?
Evita o antipattern de lançar Exception quando o inspetor apenas cancela a câmera. Tratamento explícito e type-safe no compilador.
🎙️ Roteiro de Fala — Minuto 5:00 a 6:15

"Aqui vemos o contrato de domínio. Notem que FotoCapturada exige hash, dimensões e URI no FileSystem — nenhuma menção a base64, cumprindo o §1.4. Além disso, modelamos o resultado da câmera como uma união discriminada ('sucesso', 'cancelado', 'erro'). Fechar a câmera não é uma exceção de sistema, é uma escolha de fluxo do usuário que o TypeScript obriga a tratar."

Tópico 6 • Adaptadores Expo

APIs Modernas do Expo: A Infraestrutura se Adequa ao Domínio

expo-image-picker & expo-location
Adapter: CameraGatewayExpo
export class CameraGatewayExpo implements ICameraGateway { async capturarFoto(opts?: CapturaFotoOptions): Promise<ResultadoCaptura> { const res = await ImagePicker.launchCameraAsync({ mediaTypes: ['images'], quality: opts?.qualidade ?? 0.8, allowsEditing: false, }); if (res.canceled) return { status: 'cancelado' }; const asset = res.assets[0]; return { status: 'sucesso', foto: { uri: asset.uri, largura: asset.width, altura: asset.height, tamanhoBytes: asset.fileSize ?? 350000, hash: `sha256_${Date.now()}_foto.jpg`, timestamp: new Date(), }, }; } }
Adapter: LocationGatewayExpo
export class LocationGatewayExpo implements ILocationGateway { async obterPosicaoAtual(): Promise<LocalizacaoDispositivo> { const pos = await Location.getCurrentPositionAsync({ accuracy: Location.Accuracy.High, }); return { latitude: pos.coords.latitude, longitude: pos.coords.longitude, precisao: pos.coords.accuracy ?? undefined, timestamp: new Date(pos.timestamp), }; } }
Por que launchCameraAsync e não CameraView?
Para vistorias periciais, a câmera do sistema operacional oferece foco automático nativo, flash controlado por hardware e devolução direta do URI de arquivo, sem peso de renderizar um preview customizado dentro da árvore React.
🎙️ Roteiro de Fala — Minuto 7:30 a 8:45

"Vejam a elegância dos adaptadores: CameraGatewayExpo e LocationGatewayExpo encapsulam toda a complexidade do Expo. Usamos launchCameraAsync do expo-image-picker, que aciona a câmera nativa do sistema operacional com foco por toque e compressão, e getCurrentPositionAsync com Accuracy.High do expo-location. Os adapters convertem as respostas do Expo para os objetos de domínio puros do SindiFlow."

Por que proibir base64 no SQLite (§1.4)?
Uma imagem em base64 consome 33% mais espaço e fragmenta o arquivo de banco B-Tree. No SindiFlow, o SQLite guarda apenas a URI do arquivo e metadados, enquanto o arquivo binário comprimido reside de forma segura no expo-file-system.
🎙️ Roteiro de Fala — Minuto 8:45 a 9:30

"Por fim, a persistência. Conforme a Seção 1.2 das nossas obrigações técnicas, o SQLite é a fonte da verdade offline. Toda coordenada de GPS capturada é persistida na tabela vistorias com precisão em metros e timestamp. As fotos são salvas em fotos_evidencia armazenando o caminho de arquivo do FileSystem, nunca base64, preservando a performance do banco. Toda escrita ocorre em transação com enfileiramento na Outbox para sincronização posterior."
