## 2. O que está faltando (não implementado)

### 🔴 Crítico — SQLite não está conectado (maior discrepância)

O `chat_history/2026-10-30.md` afirma que a **Fase 1 está concluída** (SQLite como fonte da verdade). **Não é verdade.** O `VistoriaContext.tsx` (linhas 188–190) ainda instancia:

```ts
const vistoriaRepo = new VistoriaRepositoryInMemory();
const ocorrenciaRepo = new OcorrenciaRepositoryInMemory();
const outboxRepo = new OutboxRepositoryInMemory();
```

Os repositórios SQLite existem no disco, mas **nenhum código de produção os importa**. O app continua 100% em memória volátil, violando §1.2 do `sindiflow-obrigacoes.md`.

### 🔴 Crítico — Nenhuma integração com Supabase (Fase 3, não iniciada)

- `@supabase/supabase-js` **não está** no `package.json`
- Não existe `src/infra/supabase/`
- Não existe `SyncGatewaySupabase` (só `RemoteSyncGatewayFake`)
- `sync_log` existe no DDL mas **nada escreve nele**
- Não existe last-write-wins com `updated_at`
- O outbox acumula eventos mas nunca sincroniza com a nuvem

### 🔴 Crítico — Nenhuma autenticação real / SecureStore (Fase 4, não iniciada)

- `AutenticarUsuarioUseCase` é mock com 3 usuários hardcoded
- `expo-secure-store` está instalado mas **não usado**
- Não existe `UsuarioRepository`, `AuthGateway`, `SessionStorageSecureStore`
- Não existe tela de login (`app/login.tsx` ausente)
- Não existe sessão de 7 dias com aviso 1 dia antes e bloqueio total ao expirar

### 🟡 Alto — Gateways reais faltando (Fase 2 lotes 3 e 4)

- `expo-network` instalado mas não usado em produção (só `NetworkServiceFake`)
- `expo-file-system` instalado mas não usado como gateway dedicado
- Não existe `INetworkService` implementação real

### 🟡 Médio — Outras faltas

- Sem `openDatabaseSync` nem migrations (`PRAGMA user_version`)
- `src/infra/` não está no `coverageThreshold` do `jest.config.js`
- Sem RNTL / testes de tela (C-14: `react@19.2.3` vs `test-renderer@^1` exigindo `react@^19.3.0`)
- Sem `ErrorBoundary`, sem acessibilidade, sem indicador visual de sync
- Dead-letter (`FALHA_MAXIMA`) invisível na UI, sem botão `resetar()`

## 4. Novas decisões desta sessão

### 4.1 Google Auth (Sign in with Google)

O usuário solicitou a adição do Google Auth. Avaliação contra o `sindiflow-obrigacoes.md` v1.3.0:

- **Não viola obrigações** — a lei não menciona provedor de autenticação específico
- **§1.1**: fluxo OAuth deve rodar nativo (`expo-auth-session` com deep linking, sem navegador web)
- **§1.2**: token em `expo-secure-store` (nunca `AsyncStorage`); dados do usuário em SQLite
- **§2**: `AuthGatewayGoogle` em `adapters/gateways/`, implementando interface de `domain/interfaces/`
- **§1.3**: criação/atualização de usuário após login com Google enfileirada na outbox
- **§4.1**: TDD obrigatório, teste antes do código

**Decisão:** Google Auth será adicionado como **provedor social dentro do Supabase Auth**, não como sistema separado. Isso mantém a decisão de 07/09/2026 (Opção C: Supabase Auth + sessão cacheada) e amplia com login social.

### 13.6 Decisão: `expo-auth-session` sem `expo-web-browser` (conformidade com §1.1)

**Decisão do usuário:** Não usar `expo-web-browser` para o fluxo OAuth do Google. O `expo-web-browser` foi removido na sessão de 13/10/2026 (T-03) por violação direta de §1.1 ("PROIBIDO: qualquer menção a implementação web, PWA ou browser"). A alternativa adotada é usar exclusivamente `expo-auth-session` com `promptAsync()` e deep linking nativo via `expo-linking`, que abre o navegador do sistema de forma nativa sem trazer dependências web para dentro do aplicativo.

**Justificativa:** Embora o app precise de internet para logar (não sendo offline-first na autenticação), o §1.1 proíbe especificamente dependências de browser/web no código. O `expo-web-browser` traz implementação de navegador embarcada, o que fere a letra da obrigação independentemente de o app precisar de rede para autenticar.

**Impacto no código:**
- `auth-gateway.google.ts`: não importa `expo-web-browser`; usa apenas `expo-auth-session` com `AuthSession` e `expo-auth-session.discovery()`.
- `package.json`: não adicionar `expo-web-browser`.
- `app.json`: já não declara plataforma web; `expo start --web` permanece proibido.

**Itens afetados:** 4.1 (`expo-auth-session` instalado, sem `expo-web-browser`), 4.4 (`AuthGatewayGoogle` sem import de browser).
